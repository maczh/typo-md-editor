## 块手柄：补全 "::" 手柄菜单（EditorPane.vue）

- Crepe 的 `.milkdown-block-handle` 内有两个 `.operation-item`：
  **[0] = "+"（Crepe 自带 onAdd，会开 slash 菜单）**、**[1] = "::" 拖拽把手（无任何事件）**。
  结构确认自 `node_modules/@milkdown/crepe/src/feature/block-edit/handle/component.tsx`。
- 结论/坑：**"::" 的 pointerdown 绝对不能 `preventDefault()`** —— 它会抑制兼容性
  mousedown，进而杀死原生 HTML5 块拖拽（BlockService 绑的是 mousedown/mouseup/
  dragstart/dragend）。"+" 则可以也必须用 preventDefault+stopPropagation 抢下 Crepe 的 onAdd。
- 点击 vs 拖拽用 4px 位移阈值区分；补了 `pointercancel` 清理挂起的 press（原生拖拽结束
  不一定有配对的 pointerup，否则下次误触会弹菜单）。
- 菜单分工："+" → `sub='insert'` 插入菜单；"::" → `sub='style'` 块类型菜单（拖拽保留）。

## 编辑区宽度 = 父容器 80%

- 链路：settings.contentWidth(默认80) → `applyLayout()` 写 `--content-width` 到
  documentElement → `.milkdown { width: var(--content-width) }`，其父容器是 `.milkdown_root`。
- 原本默认值不一致：variables.css 是 70%、CSS 回退 70%、applyLayout 兜底 70、
  i18n resizeHint 写"双击恢复 70%"，而 settings/MdEditor props 已是 80。**已全部统一为 80**。

## 手柄回归修复（浏览器实测，第二轮）

用户报障后用 agent-browser 连其运行中的 dev server（端口 1420 被占 = 用户 dev 在跑，直接连 `http://localhost:1420/?e2e=1`，`window.__typo` 可驱动编辑器）实测定位，三个根因：

1. **floating-ui `shift` 轴向陷阱**：placement 为 left/right 时，`shift()` 默认
   `mainAxis` 映射到**纵轴**（enabled={y:true,x:false}），水平裁剪根本不管。
   必须 `shift({ padding, crossAxis: true })` 才钳制水平。实测确认。
2. **手柄胶囊几何**：胶囊 58px + offset 16 + ProseMirror 左 padding 48 →
   内容列左留白 < 26px（即 contentWidth ≳ 97%）时，胶囊被 `.milkdown_root`
   的 overflow:auto 裁剪："+"（左项）先没 → 用户看到"::"正常但"+"隐藏；
   极端时整个胶囊只剩残影。修法=上面的 shift middleware。
3. **`Editor.destroy()` 是异步的**（返回 Promise<Editor>）：loadMarkdown 里
   `void destroy()` 后立刻 spawn，新旧实例争抢同一 root → 导入后手柄错位/丢失/
   菜单点不出的竞态温床。已改为 await destroy + loadSequence 序号守卫。

其他：菜单锚点探测改为取 ProseMirror 内容盒内点（`prose.viewDomRect` 新导出），
不再锚手柄矩形外扩（手柄被挪位/裁剪时旧探测落空 → 菜单弹不出）。

### 浏览器自动化踩坑（agent-browser）

- **/tmp 每次工具调用是独立 tmpfs**，跨调用不保留 → 诊断脚本放 `/home/macro/tmp/browser-diag/`。
- demo vite root=`demo/`，src 模块 URL 是 `/@fs/<绝对路径>`；直接 fetch `/src/...` 会拿到 SPA fallback 的 index.html（curl 也一样，别被 200 骗）。
- demo 的 `input[type=file]` 是 hidden，CDP upload 不触发 change；用
  `DataTransfer` + `new File(...)` + `dispatchEvent(new Event('change'))` 走真实 @change。
- 单独调用 eval 可能落在 about:blank；把 open+eval 串在同一条命令里最稳。
