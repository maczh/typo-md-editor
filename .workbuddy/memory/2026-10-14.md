
## 块手柄菜单三轮修复（用户实测反馈）

- **"+" 手柄**：交还 Crepe 原生 `pointerup → onAdd`（插空行 + slash 菜单）。此前我们拦截它弹自定义插入菜单是错的；且菜单打开后 `.ctx-layer` 全屏遮罩会吃掉下一次 pointerdown，漏掉的 pointerup 穿透到 Crepe，造成"第一次弹错菜单、第二次才弹 slash 菜单"的错乱。
- **"::" 手柄菜单动作全部失效的根因链**（逐层定位）：
  1. 探测点 `pmRect.left+24` 落在列表缩进外的沟槽 → `posAtCoords` 返回块边界 pos → `TextSelection.near` 前推进错块 → 命令作用错位/静默失败。修复：探测 x 用内容列中线（`pmRect.left + width/2`），任何行的中线必在线盒内。
  2. `blockKindAt(边界pos)` 会误判为 paragraph → 改用 setCaret 之后的 caret pos 计算块类型。
  3. **点击手柄本身会引发布局重排**：Crepe 在 handle mousedown 派发 `NodeSelection`+focus，触发字体度量交换/部件重排（实测 H1 高度 120→66px），menu 打开时再探测坐标就落到另一行。修复：**pointerdown 时捕获目标 pos 存入 handlePress，pointerup 直接使用**，不再二次探测。
  4. markdown 不允许 list_item 内嵌 heading/blockquote → 列表行上"标题/正文/引用"静默无效。修复：`prose.ts` 加 `liftFromList()`（Typora 式先把该行 lift 出列表再 setBlockType/wrapIn），应用于 setHeading/setParagraph/toggleBlockquote。

## "+" 手柄：取消选择时回滚空行

- 需求：点 "+" 调 Crepe 原生 slash 菜单，**选中菜单项后**才"先新建空行再套用样式"（即未选中就不该留下空行）。
- 关键约束（实测）：Crepe 菜单不能架在非空行上调起——`MenuView.shouldShow` 会把 `filter` 设成当前行文本，
  `getGroups` 过滤后为空 → watcher 立刻 `hide()`。所以"延迟插入空行"必须先有一个空块，无法绕过。
  结论：只能沿用 Crepe `onAdd`（点击即插空行+弹菜单），再在**未选中时回滚**。
- 实现（`EditorPane.vue` + `prose.ts`）：
  - `HandlePress` 加 `item: 0|1`；"+" 不拦截事件（Crepe 的 onAdd 必须跑），只在 pointerup 后 `setTimeout(0)` 调 `trackPlusBlank()`。
  - `trackPlusBlank()`：记录新空段的 caret pos，MutationObserver 盯 `.milkdown-slash-menu[data-show]`（Crepe `hide()` 只写该属性）。
  - "已应用"标记两处：document 捕获 pointerup 命中 `.milkdown-slash-menu li[data-index]`（点击选择）；
    window 捕获 keydown Enter（键盘选择）——**必须 window 捕获且早于 Crepe 注册**（Crepe 在菜单显示时才注册 window keydown，
    组件 mount 时注册的排在其前；document 晚于 window，不能用）。
  - `prose.ts` 新增 `deleteEmptyBlockAt(editor,pos)`：仅当该顶层块仍是**空 paragraph** 时才 delete（输入过文字/已转样式就不动）。
- 实测（真实鼠标事件）：Esc 回滚✓、点别处回滚✓、选 H2 保留✓、选 Text 保留✓、输入文字保留✓、Enter 选择保留✓、连点两次"+"后 Esc 全回滚✓；"::" 菜单回归✓。
- 注意：本轮 agent-browser 首次调用被沙箱拦截（/run/user/1000/agent-browser、/tmp 组件缓存、字体读取），需 `dangerouslyDisableSandbox` 才能跑。

## "+" 改为「只弹菜单、不预插空行」+ "::" 剪切/复制/删除改块作用域

- **硬约束（已实证）**：Crepe 原生 slash 菜单**无法**架在非空块上。`MenuView.shouldShow`
  拿 `SlashProvider.getContent()`（= 光标**之前**的本块文本）当过滤词，`getGroups` 过滤后为空
  → watcher 立刻 `hide()`；且 `isSelectionAtEndOfNode` 要求光标在块尾，两者同时成立时块必为空。
  所以"不插空行 + 用 Crepe 原生菜单"不可实现。上一轮的"点击即插空行、取消回滚"方案被用户否决
  （空行是可见的）。
- **最终方案**："+" 改为拦截 Crepe 的 `pointerup`（`preventDefault + stopPropagation`，
  并手动移除 `active` 类，因为 Crepe 是在同一 handler 里移除的），弹出**我们自己的浮动菜单**
  并预展开「插入」子菜单；空行通过 `useEditorMenu` 新增的 `beforeRun` 钩子在**选中项时**才创建
  （`insertBlockAfter` 在目标块后插空段并落光标），随后才执行该菜单项 → 即"先新建空行再应用"。
- **"::" 剪切/复制/删除错位根因**：`deleteBlock` 用 `doc.forEach` 扫描 `pos >= offset && pos <= nodeEnd`，
  当光标正好落在**两块边界**时先命中**上**一个块（故"针对上面的几行"，若上面是列表就是几行）。
  改为 `prose.blockRangeAt()`（`$pos.before(1)` + `doc.nodeAt`，depth 0 时前移一格）。
  另：剪切/复制原本读当前选区，而手柄菜单开出来的是**折叠光标** → 直接 toast"请先选中…"或复制失败，
  观感就是"没作用到当前行"。改为无选区时以**整块**为作用域（Typora 语义），新增 `getRangeText`。
- 实测：+ 点击不插行✓ / 选表格→表插在 H1 后且无残留空行✓ / 选分割线✓ / Esc 无残留✓ / 连点✓；
  "::" 删除删当前块✓、列表项删整个列表✓、复制后 Ctrl+V 得 H1 文本/列表文本✓、剪切删当前块✓；右键菜单回归✓。

**用户报告**：① `npm run dev` 打开页面出现 2 段相同 markdown，第一段 "+"/"::" 手柄点击无响应；② 导入 md 变成追加而非替换；③ 第二段文档 "::" 菜单正确但 "+" 菜单错误，应为「新增行样式菜单」。

**根因（①，一并解释②③）**：`useMilkdown.mount` 竞态。`createEditor` 是异步的（Crepe 跨多个微任务建 DOM），React 18 StrictMode 的 mount→cleanup→mount 循环里，cleanup 的 `destroy()` 执行时 store 还是空的（mount 未 resolve）→ no-op；两次 mount 都落地 → 同一容器两个编辑器。表现为：文档显示两遍；`document.querySelector('.milkdown-block-handle[data-show="true"]')` 与 `getEditor()` 总对上第一个（孤儿）实例 → 第一段手柄 pos 探测落在第二个实例视图外 → null → 无响应；悬停第二段时两个手柄同时 data-show（BlockProvider 不在 pointerleave 时隐藏），querySelector 抓到第一个 → 菜单位置/作用块全错；导入时 `loadMarkdown` 只替换存活实例 → 看起来像"追加"。

**修复**：
- `src/composables/mountSequence.ts`（新）+ `useMilkdown.ts`：`createMountSequence()` 序号守卫——`mount()` 取 token，`destroy()` 先 `invalidate()`；`createEditor` resolve 时 token 过期则自毁该实例不入 store。StrictMode 下最终只剩最新实例。
- `src/milkdown/setup.ts`：`destroy()` 移除 root 上的 paste 监听并置 `destroyed` 标志（否则被丢弃实例的监听器残留，会对已销毁 editor 调 `action`）。
- `src/components/editor/EditorPane.tsx`：`openPlusMenu` 预展开子菜单 `'insert'` → `'style'`。"+" 是新增行，应弹出「段落/标题」样式菜单（新增行样式菜单）；选中后才经 beforeRun 建空行再套样式（用户最早的需求原文即"先新建空行再套用样式"）。插入类内容仍可从同一菜单悬停「插入▸」到达。

## 晚三：用户实测两 bug——"+" 手抖点击漏 Crepe slash 菜单 + 右侧大纲边栏缺失

**用户报告**：① 左边 "+" 手柄单击弹出的菜单与行首输入 "/" 弹出的菜单相同（截图：Text/List/Advanced 标签页的 Crepe slash 菜单）；② 右边浮动边栏 sidebar 要显示文档大纲。

**根因①（已实证复现）**：Crepe 的 "+" 是**元素级** `pointerup` → `onAdd()`（插空行 + 弹 slash 菜单，见 `@milkdown/crepe/lib/esm/feature/block-edit/index.js` 的 BlockHandle Vue 组件）。我们的 `onHandlePointerUp` 在「按下到释放位移 > 4px」时**直接 return**（该阈值本为区分 "::" 拖拽），没走到 `stopPropagation` → Crepe 原生 onAdd 触发 → 空行 + slash 菜单。手抖点击（真实鼠标常见，"+ "按钮 32px 宽，漂移 6px 仍落在按钮上）必现；规范点击（CDP 无漂移）不现，所以上一轮验证漏掉。实测：漂移 6px 释放 → slash 菜单 display:block、段落数 2→3。

**修复①**（`src/components/editor/EditorPane.tsx` `onHandlePointerUp` 重写）：只要释放落在手柄按钮上就**无条件** `preventDefault+stopPropagation`（我们菜单接管手柄期间 Crepe 原生行为永不该触发），之后再判断是否开菜单；唯一豁免是真 "::" 拖拽（press/release 都在 "::" 且位移 > 4px）——块拖拽走的是 `mousedown/dragstart` 原生 HTML5 拖拽（见 `@milkdown/plugin-block`），与 pointer 事件无关，原样放行。注意 Crepe "+" 的 pointerdown 自带 preventDefault，连 mousedown 都发不出，所以 "+" 根本没有拖拽语义，任何落在 "+" 上的释放都算点击。

**根因②**：`demo/style.css` 自第一个提交起就只有 22 行基础样式（html/body/#app），`.demo-shell/.demo-toolbar/.demo-body/.demo-main/.demo-side` 等 demo 外壳类**从未有任何 CSS 定义** → aside 被渲染成编辑器下方 52px 高的全宽细带。OutlinePanel 数据链本身是通的（mount/change/loadSignal 三处 setOutline，导入后 9 个标题全部出来）。

**修复②**（`demo/style.css` 全文重写，约 175 行）：完整 demo 外壳——顶栏（btn/demo-field/demo-check）、主体 flex 行、`.demo-side` 右侧浮动大纲卡片（`flex:0 0 var(--panel-width)` + border + radius + `box-shadow: var(--shadow)`，贴右边缘），`.demo-side-title` 头栏，`.demo-side .outline-panel` 独立滚动（flex:1 + overflow-y:auto），状态行；≤1024px 时边栏改绝对定位悬浮覆盖层。全部走包内设计令牌（--bg/--panel-bg/--border/--fg-muted/--radius/--shadow/--panel-width），主题切换自动跟随。
